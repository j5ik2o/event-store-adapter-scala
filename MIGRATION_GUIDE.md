# Migrating the Scala 1.x API and stored data

This source uses Java `2.0.0-SNAPSHOT`. The Scala artifact version is generated by the existing sbt-dynver configuration. Common contract v4, conformance data 1.0.0 and DynamoDB `layout_version=1` are separate versions.

## Public API changes

| Previous Scala API | Current Scala API |
|---|---|
| `EventStore[AID,A,E]`, `EventStoreAsync[AID,A,E]` | `EventStore[P,A]`, `EventStoreAsync[P,A]` |
| Factories return stores directly | Synchronous factories return `Try`; asynchronous factories return `Future` |
| Domain `Aggregate`, `Event`, custom `AggregateId` implementations | Arbitrary serializable domain types inside Java `core.EventEnvelope` and `SnapshotEnvelope`; `AggregateId.of(typeName, value)` |
| Mutable `with...` options and event/snapshot serializers | Creation-time `EventStoreConfig`, `PayloadSerializer<T>` and storage retention policy |
| Two table names, shard count, key resolver, journal index | `DynamoDbTableConfig` with three tables and a snapshot history index |
| `persistEvent(event, version)` | `persistEvent(eventEnvelope)` |
| `persistEventAndSnapshot(event, aggregate)` | `persistEventAndSnapshot(eventEnvelope, snapshotEnvelope)` |
| `getLatestSnapshotById(Class, id)` | `getLatestSnapshotById(id)` returning two levels of optionality |
| `getEventsByIdSinceSequenceNumber(Class, id, start)` | `getEventsByIdSinceSeqNr(id, start)` returning complete envelopes |
| Old read/write/deserialization exceptions | The five Java `core` exception categories; deserialization also uses `SerializationException` |

Bind payload and aggregate-state serializers at creation. Serialize domain content only; put the aggregate identifier, sequence, event time and manifest in their envelope fields. The library does not interpret manifest values. Use verified type names and identifier values; do not infer them from the previous string representation.

Sequence 1 creates an aggregate. Every later event immediately follows the head; no version expectation is passed. Snapshot and event sequences must match when committed together. Duplicate or stale numbers are optimistic lock failures; gaps are contract violations exposing `rule()` and `seqNr()`.

The outer `None` from latest-snapshot reads means no head exists. A present result with `snapshot=None` means an existing aggregate without a snapshot. Replay from 1 in that case, or from `snapshot.seqNr()+1` otherwise. Keep the returned snapshot even when its sequence exceeds `headSeqNr`; do not use the head as the replay start or upper bound. See the complete [restoration example](README.md#save-and-restore).

## Manual data rewrite

The new library reads the new layout. The supported migration is an old-version read, application-owned conversion and new-envelope rewrite into separate tables.

1. Control old-store writes and retain the old data and its verified domain/schema information throughout migration.
2. Use the old Scala/Java library and the application's old serializers to read every event for each aggregate. Inspect any old snapshot's state and sequence before using it.
3. Explicitly map the old identifier to a verified type name and value. Separate payload from envelope metadata, preserve the verified event time and choose manifests from known schema information. Verify a consecutive event history beginning at 1 before writing. Resolve missing records or information from actual data rather than inserting guessed values.
4. Provision separate journal, snapshot and head tables with the [new schema](docs/DATABASE_SCHEMA.md). Keep old and new table sets separate. Enable snapshot `ttl` only when using TTL retention.
5. Call `EventStore.ofDynamoDB(client, tables, config)` and inspect its `Try`, or await the success of `EventStoreAsync.ofDynamoDB(asyncClient, tables, config)`. The factory initializes or validates the three configuration records with one store identity and layout version.
6. Write converted events in consecutive ascending sequence order with `persistEvent`. To save a converted snapshot, use `persistEventAndSnapshot` while appending its matching event. There is no snapshot-only write operation. Do not copy old versions, shard keys or metadata-bearing JSON unchanged.
7. Read back every envelope and restore aggregate state with the new public API. Compare the result with the verified converted payloads, sequences, timestamps, manifests and states. Preserve classified failures rather than replacing them with empty results.
8. Switch the application's reads and writes after verifying the rewritten store. The application owner decides when to remove old tables; this guide performs no deletion.

Check the original timestamp representation and precision before converting it to `Instant`. If the old data contains milliseconds only, preserve exactly those milliseconds. Do not infer the old time unit or restore lost nanoseconds, type information or identifiers from guesses or the current time.

After an interrupted rewrite, inspect already committed sequences before resuming. Reappending committed numbers causes optimistic lock failures. Do not add old-format fallback reads to the new library.

## Storage and retention

Pass the same `MemoryStorage` to share state across synchronous and asynchronous instances; omitting it isolates each creation. Memory has no TTL retention or change feed.

Configure `RetentionPolicy.none()`, `delete(n)` or, for DynamoDB, `ttl(n, graceSeconds)` on the storage settings. Counts are at least 1 and TTL grace is nonnegative seconds. Default retention keeps only the current snapshot. Marked history is excluded from the retained count and its expiry is not extended.

Retention failure after commit preserves write success and uses the separate log/listener path with the original cause. Java owns the storage operations and retries. SDK clients remain caller-owned.
